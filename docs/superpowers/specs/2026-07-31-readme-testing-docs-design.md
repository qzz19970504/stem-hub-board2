# README 与测试流程文档设计

## 目标

为板2固件提供两个位于仓库根目录、用途明确且互相链接的入口文档：

- `README.md` 面向固件开发和后续维护人员，解释项目用途、软件控制逻辑与代码架构。
- `TESTING.md` 面向开发及硬件联调人员，提供可重复执行、可记录结果的测试流程。

文档必须以当前 `master` 实现为准，不引入尚未实现的功能，也不把实板测试描述为已经完成。

## README.md 设计

README 采用“先运行，再理解”的阅读顺序：

1. 项目简介与当前能力。
2. 快速开始：依赖、主机测试、Debug/Release 构建。
3. 硬件资源与默认状态。
4. 软件控制逻辑：
   - 上电初始化与 FreeRTOS 启动顺序。
   - UART1 AT 命令与非 AT 帧的分类和分发。
   - UART2/3 接收事件回传。
   - NMOS、PWM、LED2 的控制方式。
   - UART 错误、缓冲溢出和超长帧恢复。
5. Mermaid 数据流图，展示 ISR、环形缓冲、任务、输出和三路 UART 的关系。
6. 三任务职责、优先级和栈大小。
7. `App/Inc`、`App/Src` 及 CubeMX 生成层的模块边界。
8. 关键配置、协议入口、构建产物和开发注意事项。
9. 指向 `TESTING.md` 和现有协议文档的链接。

README 不重复测试文档中的每个验证步骤，只给出快速自动验证命令。

## TESTING.md 设计

测试流程按风险和依赖顺序组织：

1. 测试范围、尚未完成的实板验证声明。
2. PC 软件与硬件仪器准备。
3. 主机单元测试。
4. Debug/Release 固件构建及成功判据。
5. 烧录前静态检查和接线表。
6. 上电安全状态：NMOS 全关、LED2 常亮。
7. NMOS、PWM、AT 严格格式测试。
8. UART2、UART3、双目标透传和二进制 HEX 回传测试。
9. 无目标、非法参数、超长行、接收溢出和串口错误恢复测试。
10. 可复制填写的最终验收记录表。

每个测试项包含操作、预期结果和必要的安全提示。无法仅靠软件自动验证的项目明确标为“实板测试”。

## 一致性要求

- UART 均为 115200、8N1、无流控。
- AT 命令严格大写并以 CRLF 结束。
- NMOS1/2/3 低有效，复位默认高电平关闭。
- PWM 位于 PB9/TIM4_CH4，约 1 kHz，范围为 0%～100%。
- UART 接收采用 Receive-to-Idle 中断，不使用 DMA。
- 单路接收块为 64 B，环形缓冲为 256 B，UART HEX 事件最多编码 32 B。
- 文档中的命令、响应、文件名、任务栈和构建命令必须与代码核对。

## 验收标准

- 新开发者可从 README 找到工程用途、构建方法、控制逻辑和关键代码位置。
- 测试人员可仅按 TESTING 顺序完成自动测试与实板验收。
- 两份文档互相链接，且链接到现有详细协议文档。
- Markdown 无占位符、无矛盾内容，命令可直接从仓库根目录执行。
- 文档变更不包含用户现有的 IDE 配置文件或其他无关工作树内容。
