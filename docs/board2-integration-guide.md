## 1. 产品简介

板2 是一款通过串口控制的输出扩展模块，连接一条串口线即可完成全部操作：

| 能力 | 说明 |
| --- | --- |
| 电源控制 | 板载 12V、18V 两路 Buck 电源的开关 |
| 开关输出 | 三路 NMOS 开关（吸合/断开外部负载） |
| PWM 输出 | 一路 25 kHz PWM，支持亮度渐变与呼吸灯演示 |
| 串口透传 | 把主串口变成透明管道，与挂在另外两路串口上的下游设备直接通信 |
| 状态查询 | 随时查询所有输出的当前状态 |

**操作方式**：上位机通过主串口（UART1）发送文本形式的 AT 命令，模块以 `OK` 或错误码应答。进入透传模式后，UART1 变成纯数据管道，可收发任意字节。

**两种工作模式**：

```text
              AT+TRANS=x
  ┌─────────────────────┐ ──────────────→ ┌─────────────────────┐
  │       AT 模式        │                  │      透传模式        │
  │ 发送文本命令控制模块   │ ←────────────── │ 原始字节直通下游设备   │
  └─────────────────────┘    +++ 静默退出   └─────────────────────┘
```

上电后模块默认处于 **AT 模式**。

## 2. 快速上手

### 2.1 准备工作

- 一个 USB 转 TTL 串口适配器（3.3V 电平）。
- 一个串口调试工具（如 SSCOM、PuTTY、MobaXterm 等）。
- 按第 3.1 节连接线路，串口工具设置为 **9600、8 数据位、无校验、1 停止位、无流控**。

### 2.2 接线（最小连接）

| 模块引脚 | 连接 | 适配器 |
| --- | --- | --- |
| UART1 RX（PA10） | ← | 适配器 TX |
| UART1 TX（PA9） | → | 适配器 RX |
| GND | — | GND（必须共地） |

> 模块供电、下游设备接线的连接器定义见 2.4 节（占位，待补充）。

### 2.3 第一条命令

1. 给模块上电，等待 LED2（PA8）常亮（约 0.1～0.2 秒），表示系统就绪。
2. 在串口工具中发送 `AT`（注意：工具需设置为以 `\r\n` 结尾，命令必须**全大写**）。
3. 收到 `OK`，说明链路正常。
4. 发送 `AT+STATUS=?` 查询设备状态，应收到类似下面的响应：

```text
+STATUS:12V=OFF,18V=OFF,NMOS1=OFF,NMOS2=OFF,NMOS3=OFF,PWM=0,PWM_TARGET=0,PWM_TIME=500,BREATH=OFF
OK
```

上电后所有输出均为安全默认状态（电源关、NMOS 断、PWM 0%），可以放心按第 4～7 章逐项操作。

## 3. 通信协议基础

### 3.1 串口参数

模块有三路串口，参数完全一致且固定：

| 参数 | 值 |
| --- | --- |
| 波特率 | 9600 |
| 数据位 / 校验 / 停止位 | 8 / 无 / 1 |
| 硬件流控 | 无 |
| 电平 | TTL 3.3V |

| 串口 | 引脚 | 用途 |
| --- | --- | --- |
| UART1 | TX=PA9、RX=PA10 | 连接上位机，收发 AT 命令与透传数据 |
| UART2 | TX=PA2、RX=PA3 | 连接下游设备 1（透传目标，编号 `1`） |
| UART3 | TX=PB10、RX=PB11 | 连接下游设备 2（透传目标，编号 `2`） |

### 3.2 命令格式规则

发送命令时务必遵守以下规则，否则模块无法识别：

| 规则 | 说明 |
| --- | --- |
| 全大写 | `at+nmos1=on` 无效，必须写 `AT+NMOS1=ON` |
| CRLF 结尾 | 每条命令必须以 `\r`（0x0D）`\n`（0x0A）结束 |
| 无空格 | 命令中不允许空格或制表符 |
| 长度限制 | 单条命令最长 127 字节，超长返回 `+ERROR:LINE_TOO_LONG` |
| 前缀 | 必须以 `AT` 开头；不以 `AT` 开头的行会被静默丢弃（无响应） |

### 3.3 应答模型：一问一答

模块采用严格的**一问一答**模型：

```text
上位机发送一条命令  →  等待该命令的响应  →  再发下一条
```

- 命令执行成功：返回 `OK`。
- 命令被拒绝或出错：返回 `+ERROR:<原因>`（完整列表见第 9 章）。
- 状态查询：先返回 `+STATUS:...` 数据行，再返回 `OK`。
- 模块**不会主动上报**状态变化；需要状态时请主动查询。
- 命令按接收顺序逐条处理，不存在并发执行，行为完全可预期。

### 3.4 接收解析建议（面向上位机开发者）

1. 所有响应均以 `\r\n` 结尾，接收侧按行缓冲、逐行解析。
2. 行首缀分类处理：

| 前缀 | 类型 |
| --- | --- |
| `OK` | 命令成功 |
| `+ERROR:` | 命令失败，冒号后为原因 |
| `+STATUS:` | 状态查询数据 |
| `+UART2RX:` / `+UART3RX:` | 透传期间下游设备回传的数据（HEX 编码，见 8.4） |

3. 建议命令响应超时 **300 ms**（模块内部发送超时为 250 ms），超时后重试一次，连续超时判定链路异常。
4. 不要在同一帧里拼接多条命令。

## 4. 电源控制

模块内置 12V、18V 两路 Buck 电源，默认**关闭**，必须显式开启后才能使用对应负载。

### 4.1 开启/关闭

```text
→ AT+12V=ON        ← OK          开启 12V 电源
→ AT+12V=OFF       ← OK          关闭 12V 电源
→ AT+18V=ON        ← OK          开启 18V 电源
→ AT+18V=OFF       ← OK          关闭 18V 电源
```

### 4.2 联锁规则（重要）

出于安全考虑，模块内置硬件无关的软件联锁，无法绕过：

| 联锁规则 | 现象 |
| --- | --- |
| 12V 关闭时不允许开 NMOS | 返回 `+ERROR:12V_DISABLED` |
| 18V 关闭时不允许设非零 PWM 或开呼吸灯 | 返回 `+ERROR:18V_DISABLED` |
| 关闭 12V 时 | 三路 NMOS **自动全部关断** |
| 关闭 18V 时 | PWM **立即归零**，呼吸灯**立即停止** |

由此得出两条使用法则：

1. **上电顺序**：先开 12V 再开 NMOS；先开 18V 再设 PWM（完整初始化序列见 12.1）。
2. **关电源即批量关负载**：`AT+12V=OFF` 一条命令即可断开全部三路负载，`AT+18V=OFF` 即可彻底熄灭 PWM 输出，可作为紧急停止手段。但注意关闭后再开电源，负载状态不会恢复，需要重新下发。

## 5. NMOS 开关控制

三路 NMOS（NMOS1/2/3）用于通断外部负载，高电平导通，上电默认关断。

### 5.1 操作

```text
→ AT+12V=ON        ← OK          前提：先开 12V
→ AT+NMOS1=ON      ← OK          NMOS1 导通
→ AT+NMOS2=ON      ← OK          NMOS2 导通
→ AT+NMOS3=ON      ← OK          NMOS3 导通
→ AT+NMOS1=OFF     ← OK          NMOS1 关断
```

命令格式：`AT+NMOS<n>=ON` / `AT+NMOS<n>=OFF`，`n` 取 1、2、3。

### 5.2 注意事项

- 12V 未开启时执行 `AT+NMOS<n>=ON` 会被拒绝（`+ERROR:12V_DISABLED`），此时负载实际状态不变。
- `AT+12V=OFF` 会自动把三路 NMOS 全部关断，模块内部状态同步更新，用 `AT+STATUS=?` 可验证。
- 断开（OFF）操作不需要 12V 处于开启状态，任何时候都可以执行。

## 6. PWM 输出

PWM 输出（PB9）频率固定 25 kHz，占空比按 0～100 的整数百分比设置，适合调光、调速等应用。

### 6.1 设置占空比

前提：18V 必须已开启，否则返回 `+ERROR:18V_DISABLED`。

```text
→ AT+18V=ON        ← OK
→ AT+PWM=50        ← OK          亮度渐变至 50%
→ AT+PWM=100       ← OK          亮度渐变至 100%
→ AT+PWM=0         ← OK          输出关闭（渐变归零）
```

**理解"渐变"**：`AT+PWM` 设置的是**目标值**，命令返回 `OK` 时输出还没到目标，而是在渐变时间内平滑过渡（默认 500 ms）。输出经 Gamma 2.2 校正，人眼观感的亮度变化是线性的。

- 渐变过程中可以再次下发 `AT+PWM`，输出会从**当前值**直接向新目标过渡，无需等待。
- 判断渐变是否完成：等待 `PWM_TIME` 毫秒，或轮询 `AT+STATUS=?` 直到 `PWM` 字段等于 `PWM_TARGET`。

### 6.2 设置渐变时间

```text
→ AT+PWM_TIME=2000   ← OK        渐变时间改为 2 秒
→ AT+PWM_TIME=0      ← OK        关闭渐变，立即跳变
```

- 范围 0～10000 毫秒，超范围返回 `+ERROR:PARSE`。
- **掉电保存**：设置成功后写入板载 Flash，下次上电仍然生效；其余所有输出状态上电一律回到安全默认。
- 写入失败返回 `+ERROR:STORAGE`（罕见，属硬件异常）。
- ⚠️ Flash 有擦写寿命（约 1 万次），**不要**在程序里高频反复修改渐变时间（例如每次调光都先改时间）。正常用法是初始化时设置一次。

### 6.3 呼吸灯演示

呼吸灯是内置的自检/演示功能，PWM 在 0%↔100% 之间自动循环，每段时长取当前渐变时间（最短 100 ms）。

```text
→ AT+18V=ON             ← OK     前提
→ AT+BREATH_TEST=ON     ← OK     开始呼吸
   …（PWM 自动呼吸，此时发 AT+PWM 会收到 +ERROR:BREATH_ACTIVE）…
→ AT+BREATH_TEST=OFF    ← OK     停止，渐变回演示前的目标值
```

- 演示期间普通 `AT+PWM` 命令被拒绝，需先 `AT+BREATH_TEST=OFF`。
- 紧急停止：`AT+18V=OFF` 始终立即生效，会同时停止呼吸灯。

## 7. 状态查询

```text
→ AT+STATUS=?
← +STATUS:12V=OFF,18V=OFF,NMOS1=OFF,NMOS2=OFF,NMOS3=OFF,PWM=0,PWM_TARGET=0,PWM_TIME=500,BREATH=OFF
← OK
```

字段含义：

| 字段 | 含义 |
| --- | --- |
| `12V` / `18V` | 两路电源的使能状态（ON / OFF） |
| `NMOS1/2/3` | 三路 NMOS 的通断状态 |
| `PWM` | PWM **当前实际**百分比（渐变过程中可能与目标不同） |
| `PWM_TARGET` | PWM 目标百分比 |
| `PWM_TIME` | 当前渐变时间（ms），即掉电保存值 |
| `BREATH` | 呼吸灯是否在运行 |

使用时机建议：

- 上电初始化后立即查询一次，与本地缓存同步；
- 收到 `+ERROR:RX_OVERFLOW` 等异常后重新同步；
- 对输出状态有疑问时，以本查询结果为准。

## 8. 透传模式

透传模式把 UART1 变成一根**透明数据管道**：你往 UART1 发送的原始字节会原样到达下游设备（UART2 和/或 UART3），下游设备发回的数据则以 HEX 文本事件的形式回传到 UART1。适合与挂在下游串口上的第三方设备（如传感器、执行器、其他模块）通信。

### 8.1 进入透传

| 命令 | 目标 |
| --- | --- |
| `AT+TRANS=1` | 仅转发到 UART2 |
| `AT+TRANS=2` | 仅转发到 UART3 |
| `AT+TRANS=1&2` | 同时转发到 UART2 和 UART3 |

```text
→ AT+TRANS=1
← OK                                ← 收到 OK 即已进入透传
```

进入透传后：

- UART1 收到的**所有字节**不再解析，原样转发到选定目标；
- 内容形似 AT 命令的字节（如 `AT+PWM=100\r\n`）也只是普通数据，**不会被执行**；
- 上位机不能再发 AT 命令，必须先退出透传（见 8.5）。

⚠️ 时序注意：模块是**先回 `OK` 再切换模式**。请确保完整收到 `OK` 后再开始发送透传数据，不要把透传数据和 `AT+TRANS` 命令拼在一起发送。

### 8.2 向下游设备发送数据

直接发送原始字节即可，无需任何编码（这与 `AT+UARTTX` 的 HEX 格式不同）。例如给下游设备发 6 个字节 `01 03 00 00 00 02`：

```text
（已在透传模式）
→ 01 03 00 00 00 02      ← 下游设备在 UART2 上收到同样的 6 个字节
```

双目标模式（`1&2`）下，同一份数据会**同时**发往 UART2 和 UART3。

### 8.3 回读下游设备的数据

下游设备发回的数据不能直接以二进制回到 UART1（因为无法与事件文本区分），模块将其编码为**大写 HEX 事件**回传：

```text
← +UART2RX:0103040000781A81\r\n      下游设备回传的数据（HEX 编码）
← +UART3RX:5A\r\n
```

- 事件前缀标明来源：`+UART2RX:` = UART2 收到，`+UART3RX:` = UART3 收到。
- 冒号后是大写十六进制字符，每两个字符对应一个字节，无空格、无分隔符。
- 每个事件最多携带 **32 字节**数据；下游一次发 100 字节会收到多个连续事件，按到达顺序拼接即可还原。
- 双目标模式下，两路下游设备的事件都会回传，请靠前缀区分来源。

上位机解析步骤：按行读取 → 识别前缀 → 取冒号后字符串 → 按两位一组转回二进制 → 交给下游设备协议处理。

⚠️ **AT 模式（未进入透传）下，UART2/UART3 收到的数据会被直接丢弃**，既不缓存也不上报事件。需要下游数据时必须处于对应目标的透传模式。

### 8.4 退出透传

发送**前后各静默至少 1 ms** 的三个加号 `+++`（0x2B 0x2B 0x2B）：

```text
（停止发送，静默 ≥20ms）
→ +++
（静默 ≥20ms）
← OK                                ← 已回到 AT 模式
```

- 退出时模块清除透传目标，**未回读的下游数据被丢弃**。
- 静默条件不满足时不会误退出：`abc+++def` 整段作为数据转发；`++++` 也不会被识别。这保证了正常业务数据里恰好包含 `+++` 时不会意外退出。
- 上位机推荐做法：暂停数据发送 → 等待约 20 ms → 发送 `0x2B 0x2B 0x2B` → 再等约 20 ms → 等待 `OK`。20 ms 远大于 1 ms 要求，可靠且对吞吐影响可忽略。
- 退出后如需再次透传，重新发送 `AT+TRANS=x` 即可。

### 8.5 透传模式下的异常

| 异常 | 现象 | 模块行为 | 建议处理 |
| --- | --- | --- | --- |
| UART1 接收溢出（连续高速灌入数据超过缓冲能力） | 收到 `+ERROR:RX_OVERFLOW` | **中止透传，自动回到 AT 模式**，缓冲清空 | 重新 `AT+STATUS=?` 同步，按需重新进入透传 |
| UART2/UART3 接收溢出 | 收到 `+ERROR:RX_OVERFLOW` | 透传**保持**，该通道缓存清空，溢出期间数据丢失 | 依赖下游设备协议重传补齐 |
| 串口线缆断连重连 | 无 | 接收自动恢复，无需干预 | — |

### 8.6 透传模式完整示例

以与一个类 Modbus 设备通信为例（设备挂在 UART2）：

```text
→ AT+TRANS=1
← OK                                进入透传
→ 01 03 00 00 00 02                 发送读寄存器请求（原始字节）
← +UART2RX:010304000A001AB844\r\n   收到设备应答（HEX 编码，还原后为 01 03 04 00 0A 00 1A B8 44）
（静默 ≥20ms）
→ +++                               退出透传
（静默 ≥20ms）
← OK                                回到 AT 模式
```

## 9. 错误码速查

所有错误响应格式为 `+ERROR:<原因>\r\n`：

| 错误码 | 含义 | 典型原因 | 处理建议 |
| --- | --- | --- | --- |
| `PARSE` | 命令格式错误 | 小写字母、含空格、参数非法、未知命令 | 检查拼写与格式后重发 |
| `RANGE` | 参数超范围 | PWM 大于 100；HEX 数据超过 32 字节 | 校验参数 |
| `12V_DISABLED` | 12V 未开，不能开 NMOS | 顺序错误 | 先发 `AT+12V=ON` |
| `18V_DISABLED` | 18V 未开，不能设非零 PWM / 开呼吸灯 | 顺序错误 | 先发 `AT+18V=ON` |
| `BREATH_ACTIVE` | 呼吸灯运行中拒绝普通 PWM | 呼吸灯未关 | 先发 `AT+BREATH_TEST=OFF` |
| `UART_DISABLED` | `AT+UARTTX` 无有效目标 | 未处于透传 | 用透传模式发送数据 |
| `UART_TX` | 串口发送失败或超时 | 下游接线异常 | 重试；持续失败检查接线 |
| `LINE_TOO_LONG` | 命令帧超过 127 字节 | 命令过长 | 拆短；大数据走透传 |
| `RX_OVERFLOW` | 接收缓冲溢出 | 发送速率过高 | 见 8.5；透传被中止需重进 |
| `STORAGE` | 渐变时间写 Flash 失败 | 硬件异常 | 重试；持续失败联系售后 |

## 10. 常见问题（FAQ）

**Q1：发送 `AT` 没有任何响应。**
按顺序检查：① 波特率是否 9600、8N1、无流控；② 串口工具是否以 `\r\n` 结尾、命令是否全大写；③ TX/RX 是否接反（模块 PA10 接适配器 TX）；④ 是否共地；⑤ LED2 是否常亮（不亮说明模块未就绪，检查供电）。

**Q2：一直收到 `+ERROR:PARSE`。**
命令必须全大写、无空格、以 `\r\n` 结尾。例如 `at+nmos1=on`、`AT + NMOS1=ON`、`AT+NMOS1 = ON` 都会报此错误。

**Q3：`AT+NMOS1=ON` 被拒绝（`+ERROR:12V_DISABLED`）。**
这是安全联锁，先执行 `AT+12V=ON` 再开 NMOS。

**Q4：`AT+PWM=50` 返回 OK 但亮度没变/没反应。**
依次确认：① 18V 是否已开启；② 是否处于呼吸灯模式（`AT+STATUS=?` 看 `BREATH` 字段）；③ 输出是渐变过渡的，等待渐变时间（默认 500 ms）后再观察。

**Q5：`AT+PWM` 想立即生效，不要渐变。**
先执行 `AT+PWM_TIME=0`，之后的占空比设置即为瞬时跳变。

**Q6：进入透传后给下游发数据，下游没收到。**
确认：① `AT+TRANS` 选择的通道与下游设备所接的串口一致（1=UART2、2=UART3）；② 是否在完整收到 `OK` 之后才开始发数据；③ 是否已经无意中退出透传（例如数据里恰好带出了带静默的 `+++`）。

**Q7：透传中收不到下游设备的数据。**
确认当前确实处于透传模式（AT 模式下下游数据会被丢弃，见 8.3），且透传目标包含该下游设备所接的串口。

**Q8：透传模式下想执行 AT 命令怎么办？**
必须先退出透传：静默 ≥20 ms → 发 `+++` → 静默 ≥20 ms → 收到 `OK` 后再发 AT 命令。透传模式下任何文本都不会被解析。

**Q9：发 `+++` 没退出透传。**
`+++` 前后必须各有 ≥1 ms 静默（即发送前后不能紧贴其他数据）。建议前后各留 20 ms。另外注意只发三个加号，`++++` 无效。

**Q10：掉电再上电后渐变时间变回默认了？**
只有执行 `AT+PWM_TIME` 并收到 `OK` 才会保存；如果当时返回了 `+ERROR:STORAGE` 则未保存成功。

**Q11：模块好像"失控"了，状态和预期不符。**
先执行 `AT+STATUS=?` 查看真实状态；注意 4.2 节的联锁自动关断行为（关 12V 会连带关断全部 NMOS）。无法恢复时硬件复位模块，然后按 12.1 重新初始化。

**Q12：透传模式突然自己退出了。**
唯一自动退出途径是 UART1 接收溢出（`+ERROR:RX_OVERFLOW`）。降低上位机发送速率，或减少单帧数据量；退出后需重新 `AT+TRANS=x`。

## 11. 已知限制

- 三路串口固定 9600 8N1，不可配置；透传吞吐上限约 960 字节/秒。
- AT 命令帧上限 127 字节；`AT+UARTTX`（兼容保留）单帧上限 32 字节；大流量数据请使用透传模式。
- 下游数据回读采用 HEX 文本编码，带宽开销为 2 倍（1 字节数据占 2 字节事件），高频回读场景请评估总吞吐。
- 模块无版本查询命令，版本追溯依赖出货记录（占位：如有需要请在后续固件中补充）。
- 模块不缓存透传数据：未处于透传模式时到达的下游数据会丢失，请合理安排透传窗口。

### 12.3 设备内部运行机制（供深入理解）

固件基于 FreeRTOS 运行三个应用任务，了解它们有助于解释一些时序现象：

| 任务 | 职责 | 对使用者可见的影响 |
| --- | --- | --- |
| `systemTask` | 每 10 ms 驱动一次 PWM 渐变/呼吸灯节拍；启动时点亮 LED2 | 渐变以 10 ms 步进推进，`AT+STATUS=?` 中的 `PWM` 值按此粒度更新 |
| `atTask` | UART1 接收、AT 命令解析执行、透传转发与 `+++` 退出判定 | 命令响应及时（毫秒级）；透传吞吐受 9600 波特率限制 |
| `bridgeTask` | UART2/UART3 接收 → 编码为 HEX 事件 → 回传 UART1 | 下游数据回读有轻微调度延迟，事件可能成簇到达 |

其他参数：所有串口发送为阻塞式，单次发送超时 250 ms（超时返回 `+ERROR:UART_TX`）；UART1 接收使用 256 字节环形缓冲；渐变时间保存在片内 Flash 独立页（0x0800FC00，1 KB），追加记录、写满整页擦除重写。

### 12.4 技术规格汇总

| 项目 | 规格 |
| --- | --- |
| 串口数量 / 参数 | 3 路，9600 8N1，无流控，TTL 3.3V |
| NMOS 输出 | 3 路，高电平导通，依赖 12V 电源 |
| PWM 输出 | 1 路，25 kHz，0～100%，Gamma 2.2，支持渐变/呼吸 |
| 电源输出 | 12V、18V 两路，默认关闭，带联锁 |
| 命令帧上限 | 127 字节 |
| 透传单事件数据上限 | 32 字节（下游→上位机） |
| 渐变时间范围 | 0～10000 ms，默认 500 ms，掉电保存 |
| 透传退出方式 | `+++`（前后 ≥1 ms 静默） |

### 12.5 完整交互示例

```text
→ AT\r\n
← OK\r\n

→ AT+STATUS=?\r\n
← +STATUS:12V=OFF,18V=OFF,NMOS1=OFF,NMOS2=OFF,NMOS3=OFF,PWM=0,PWM_TARGET=0,PWM_TIME=500,BREATH=OFF\r\n
← OK\r\n

→ AT+NMOS1=ON\r\n
← +ERROR:12V_DISABLED\r\n            ← 联锁拒绝

→ AT+12V=ON\r\n
← OK\r\n
→ AT+NMOS1=ON\r\n
← OK\r\n

→ AT+18V=ON\r\n
← OK\r\n
→ AT+PWM=100\r\n
← OK\r\n                              ← 亮度在 500 ms 内渐变至 100%

→ AT+TRANS=1\r\n
← OK\r\n                              ← 进入透传
→ 01 03 00 00 00 02（原始字节）        ← 直接转发到 UART2
← +UART2RX:010304000A001AB844\r\n     ← 下游应答，HEX 编码回读
（静默 ≥20ms）
→ +++                                 ← 退出透传
← OK\r\n                              ← 回到 AT 模式
```
